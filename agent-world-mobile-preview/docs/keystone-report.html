1. Design (what was built)

  1. Keystone Claude. A roster entry (group architect, home at the Riviera Maya pit), an accessory (keystone), a label style, and a Show Buddies identity mapping (handle "Keystone Claude" → the agent, not a generic fan).
  2. Moon Palace Cancún pack (packs/moon-palace-cancun). An engine-agnostic three.js module plus a Claude Edition adapter. It has:
  3. a beach stage facing inland with the sea behind it;
  4. sand sections that match the Show Buddies sections;
  5. a pool and lobby, resort blocks with lit windows, palms, palapas and torches;
  6. a zip line that agents ride (new route legs {ride, dur} in agents.js);
  7. section-accurate fan seating (a new sim.fanPlacers hook);
  8. a moon phase for each show night.
  9. Layout search (src/architect.js). A seeded (1+λ) evolution strategy (λ = 8). It keeps the best layout (elitist), adapts its step size with the 1/5 success rule (×1.15 or ×0.87 per generation, σ ∈ [0.25, 12] m), changes the number of towers (p = 0.15) and restarts after 60 stalled generations at minimum σ.
  10. Dialog (src/dialog.js). It has:
  11. a scene catalogue with when, weight and remember per scene, plus novelty damping (weight / (1 + 0.6 × times run));
  12. a mandatory introduction scene;
  13. memory persisted in localStorage;
  14. the K3 rule (real people only quoted);
  15. a validator for optional external providers: speaker in cast, no links, and number grounding against facts plus memory.
  16. Build loop (tools/rsi/build_loop.mjs). It runs G0 (v1.2.0) → G1 (v2 features) → greedy rounds over the candidates casters, batch and screens. Gates are: no script errors, and per view ≤ 0.5% changed pixels (max channel |Δ| > 32) with mean |Δ| ≤ 1.0 against deterministic ?vtest=1 frames. A null test (baseline vs baseline) sets the noise floor.
  17. Panels. 📐 Architect (live search, measured ledger, blueprint) and 💬 Dialog (transcript, memory, a summit button).

2. Assumptions

  • A1. The layout objective is a model:
  • point sources with inverse-square spreading;
  • cardioid directivity, 0.5(1 + cos θ) with a floor of 0.1;
  • incoherent power summation;
  • no air absorption, ground reflection, wind or temperature effects.
  • A2. Delay towers are time-aligned to arrive 10 ms after the main PA on their own axis (the precedence window). A listener is flagged "echo" when a tower is within 6 dB of the main and arrives > 35 ms late or > 2 ms early.
  • A3. Sightlines are straight 2D lines from each listener to the stage centre. Towers are 0.9 m cylinders; the soundboard tent is 2.4 m.
  • A4. Venue geometry is an artistic model, not a survey of the real resort. Sections are axis-aligned boxes.
  • A5. The moon phase uses mean motion. The reference new moon is 2000-01-06 18:14 UTC and the synodic month is 29.530588853 d. Rise times come from two mean-motion anchors (sunset ≈ 18:15, sunrise ≈ 07:12 local in late January).
  • A6. The build loop's frame times come from SwiftShader (software rendering). Only draw-call counts and pixel diffs transfer to real GPUs.

3. Parameter choices

Parameter Value Why
Main PA level 120 dB SPL @ 1 m puts the pit just under the 102 dB band edge in the model
Tower level 113 dB SPL @ 1 m lifts the back section into the band at 8–15 m
Target band 92–102 dB the top is guideline-inspired (WHO venue guidance ≈ 100 dB(A) 15-min average); not a legal limit
Score weights coverage 0.35, uniformity 0.20, sightlines 0.20, echo-free 0.15, mix accuracy 0.10, −1.5 per tower, −5 per tower pair closer than 4 m coverage first, then fairness across the crowd
ES λ = 8, σ₀ = 6 m, 1/5 rule over a 10-generation window, restart after 60 stalled generations standard settings
In-world rate 1 generation / 0.7 s so people can watch it improve
Build-loop gates ≤ 0.5% changed pixels, mean |Δ| ≤ 1.0, 0 errors, ≥ 2% fewer draw calls (screens: ≥ 5% period or ≥ 10% CPU) about 5× above the measured null-test noise

5. Improvements executed beyond the request

  1. Rule K3 fix. Removed the invented lines the v1.x simulation gave Daniel, a real person. He now only quotes his own post, and scripted tasks no longer claim to come "from Daniel".
  2. Render optimization, measured and gated: G2 static batching (merge never-moving meshes per material) (1518 → 1014 home-view draw calls), G3 shadow-caster culling (tiny meshes stop casting shadows) (1014 → 911 home-view draw calls).
  3. Replayable frames. The ?vtest=1 deterministic mode, plus clock-based gears and propellers, make pixel-diff regression testing possible.
  4. Measurement switches: ?lockq=1, ?opt= and ?sb=sample. Packs now load before the first Show Buddies read, so a pack can seat fans.
  5. Batching hazard found and fixed before shipping: static detection could freeze the feet of an agent that was standing still. Avatar parts are now always dynamic. Batching also no longer merges across islands, which keeps culling working.
  6. Section-accurate seating for Riviera Maya fans (the Show Buddies section → a place on the beach).
  7. Custody repair. The moved v1.2.0 ZIP was restored byte-identically to the delivery tree, and the root START_HERE was rebuilt.

6. Limits and what is not verified

  • V1 merge status covers the public production deploy only. Daniel may have merged locally, on a branch or in a preview deploy; that cannot be seen from outside.
  • Frame times from the build loop are SwiftShader numbers. Real-GPU numbers come from one device only (see 4.2).
  • The layout score, venue acoustics and coverage map are models (A1–A3), not measurements of the real beach.
  • The moon phase is a mean-motion estimate (±0.5 day; the rise time is a window).
  • The external dialog provider hook was tested with in-process mock providers only. No LLM endpoint was connected, and no API key is involved.
  • The visual gate compares deterministic frames from three camera views. Effects outside those views (for example animation of agents that were idle) were checked by code review and the always-dynamic marking, not by pixels.
  • There were no Show Buddies requests on Conscious Claude's old post at check time. Daniel received the gift by iPhone Messages and, per Smarth Vader, asked to collaborate.
  • The Show Buddies post is public and permanent until deleted. The delete link and token are in the private receipt.
